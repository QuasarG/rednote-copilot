# RedNoteMatrix Copilot PRD

## 1. 产品概述

RedNoteMatrix Copilot 是面向小红书初级博主、种草商家、企业新媒体代运营的 AI Agent 工作台。产品不定位为“一键生成小红书文案”的聊天工具，而定位为围绕小红书热度、安全和真人感的闭环内容风控与增长 Agent。

核心承诺：

> 把普通商品卖点，转化为更安全、更像真人、更符合小红书结构的可发布笔记，并在发布前完成合规、AI 痕迹和爆款结构复检。

## 2. 机会判断

### 2.1 目标用户

- 小红书初级博主：缺少成熟方法论，容易陷入“小眼睛低”“不知道哪里有问题”的焦虑。
- 种草商家：需要持续产出商品笔记，但既怕低流量，也怕广告法和平台规则踩线。
- 企业新媒体代运营：批量服务多个账号，需要标准化结构、风控和复盘能力。

### 2.2 深层痛点

用户表面上在求文案、标题、封面建议，底层诉求其实是：

- 提高帖子热度：解决小眼睛低、浏览量低、推流弱的问题。
- 降低发布风险：避免违规、限流、审核异常、薯条不可投放。
- 保持真人感：避免普通 AI 生成的模板腔、机器味和人设破坏。

这意味着机会不在“再做一个聊天 AI”，而在做一个小红书发布链路里的 Agent：能诊断、生成、改写、检查、回炉、复盘。

### 2.3 为什么现在做

普通 LLM 的单轮聊天能力已经足够生成一段文案，但它解决不了 B 端用户真正的问题：

- 不知道平台规则风险点在哪里。
- 不知道为什么写完还是没有流量。
- 不知道标题、封面、钩子、正文结构哪里出了问题。
- 不知道 AI 文案是否太模板、太像机器。

LangGraph Multi-Agent 工作流适合把这些步骤串成闭环：

1. 爆款结构拆解。
2. 真人网感改写。
3. 合规与 AI 痕迹扫描。
4. 不通过则自动回炉修改。
5. 输出可发布版本和风险解释。

## 4. 产品定位

### 4.1 一句话定位

面向小红书种草商家和初级运营者的发布前增长风控 Agent。

### 4.2 不做什么

- 不做泛用聊天 AI。
- 不做单纯“一键生成小红书文案”。
- 不承诺绕过平台风控或保证爆款。
- 不提供刷量、互赞、规避审核等灰产能力。

### 4.3 做什么

- 结构化拆解：把卖点转成标题、封面文案、钩子、正文、标签。
- 真人化改写：降低模板腔、机器味、硬广味。
- 合规风控：检查极限词、广告法风险、平台敏感表达、AI 违规风险。
- 自动回炉：不合格则带着具体原因返回上游节点重写。
- 可解释报告：输出为什么这么改、还有哪些风险、建议怎么发布。

## 5. 核心用户场景

### 场景 A：小商户发布商品种草

用户输入：

- 商品名称。
- 核心卖点。
- 目标人群。
- 价格带。
- 希望语气。

Agent 输出：

- 爆款双标题。
- 封面文案。
- 痛点钩子开头。
- 小红书正文。
- 标签建议。
- 合规风险报告。
- AI 痕迹评分。
- 发布前优化建议。

### 场景 B：运营者低流量诊断

用户输入：

- 已发布笔记标题。
- 正文。
- 封面文案。
- 当前小眼睛/点赞/收藏/评论。

Agent 输出：

- 低热度原因诊断。
- 标题/封面/正文结构问题。
- 疑似风控风险。
- 改写版本。
- A/B 标题候选。

### 场景 C：代运营批量生产与质检

用户输入：

- 多个商品卖点。
- 多个账号人设。
- 禁用词表。
- 品牌语气规范。

Agent 输出：

- 批量笔记草稿。
- 每篇风险评级。
- 每篇结构评分。
- 可导出的审核表。

## 6. LangGraph Agent 设计

### 6.1 总体图

```text
User Input
  -> structure_agent
  -> humanizer_agent
  -> compliance_agent
  -> route:
      pass -> final_packager
      reject -> humanizer_agent / structure_agent
  -> final_output
```

### 6.2 State 设计

```python
class RedNoteAgentState(TypedDict):
    user_input: dict
    product_profile: dict
    target_audience: str
    account_persona: dict
    draft: dict
    structure_score: float
    human_score: float
    compliance_score: float
    ai_trace_score: float
    risk_items: list[dict]
    revision_history: list[dict]
    final_output: dict
```

### 6.3 Node 1: structure_agent

目标：

把干瘪卖点转成小红书笔记结构，而不是只生成正文。

输入：

- 商品卖点。
- 目标用户。
- 使用场景。
- 账号定位。

输出：

- 爆款双标题。
- 封面文案。
- 痛点/情绪钩子开头。
- 正文结构。
- 标签建议。
- 结构解释。

约束：

- 内部状态以结构化对象传递，普通用户界面不直接展示 JSON。
- 必须说明使用了哪类结构：痛点型、反差型、避坑型、清单型、测评型、故事型。
- 不得直接使用绝对化承诺。

### 6.4 Node 2: humanizer_agent

目标：

把结构化草稿改成更像真实 KOC，而不是广告稿或 AI 模板。

输入：

- structure_agent 的草稿。
- 账号人设。
- 语气偏好。

输出：

- 真人化正文。
- 口语化标题候选。
- 情绪浓度控制。
- AI 味修改说明。

规则：

- 去掉过度营销词。
- 避免“绝绝子”“家人们”这类过拟合套话。
- 保留轻微口语停顿和真实体验感。
- 不制造虚假体验。

### 6.5 Node 3: compliance_agent

目标：

作为整个图的核心风控节点，模拟发布前审稿。

检查项：

- 广告法极限词：最、第一、顶级、绝对、永久、100% 等。
- 平台风险词：引流、私信、返现、保证效果、医学功效等。
- AI 痕迹：模板化表达、空泛形容词、重复句式、过强营销腔。
- 隐形限流风险：标题党、夸大承诺、违规导流、过度诱导互动。

输出：

```json
{
  "pass": false,
  "compliance_score": 72,
  "ai_trace_score": 64,
  "risk_items": [
    {
      "type": "extreme_claim",
      "text": "绝对有效",
      "reason": "广告法极限承诺风险",
      "suggestion": "改为“我自己用下来比较有感”"
    }
  ],
  "route_to": "humanizer_agent"
}
```

路由规则：

- `pass = true`：进入 final_packager。
- `compliance_score < 80`：回到 humanizer_agent。
- `structure_score < 70`：回到 structure_agent。
- `ai_trace_score > 60`：回到 humanizer_agent。
- 循环次数超过 3 次：输出当前最优版本和剩余风险。

### 6.6 Node 4: final_packager

目标：

把最终结果包装成可复制、可审核、可复盘的交付物。

输出：

- 最终标题。
- 备选标题。
- 封面文案。
- 正文。
- 标签。
- 评论区引导建议。
- 面向用户默认只展示可复制内容。
- 风险报告、修改历史、发布建议进入调试视图或工作台审核面板。

## 11. 风险与边界

### 11.1 不能承诺规避平台风控

产品只能做风险提示和内容优化，不能承诺绕过审核或保证不被限流。

### 11.2 不能鼓励刷量互赞

数据中存在大量互看、互赞、回访内容，但产品不应支持这类灰色增长方式。

### 11.3 不能伪造真实体验

真人网感改写必须基于用户提供的真实素材，不能编造使用经历、疗效、交易结果。

### 11.4 数据结论要谨慎

AI 相关显性讨论占比不高，因此对外叙事应避免“用户最痛的是 AI 味”。更准确的说法是：

> 用户最痛的是低热度和限流违规；AI Agent 是解决这个链路的自动化工具。

## 13. 一页纸总结

RedNoteMatrix Copilot 的机会不在“替用户写一段更像小红书的文案”，而在解决小红书 B 端运营者的核心焦虑：低热度、违规限流和内容不可信。

数据证明：

- 流量/可见性焦虑是最大主题，覆盖 810 条评论。
- 违规/限流/审核风险覆盖 201 条评论。
- 结构化爆款框架与流量焦虑存在明确共现。
- AI 显性讨论不高，但 AI 与违规、模板化、信任问题存在直接证据。

因此，产品应定位为：

> 面向小红书种草商家和初级运营者的 AI Agent 增长风控工作台。

核心能力：

- 合规防限流 Agent 是底座。
- 结构化爆款 Agent 是增长矛。
- 真人网感改写 Agent 是信任盾。
