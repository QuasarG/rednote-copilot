## 抽象出的通用规律

1. 标题先给情绪或悬念，再交代对象。
2. 强场景优先于强卖点，具体生活瞬间比产品说明更容易触发代入。
3. 轻反差比硬夸更像真人，例如“本来以为普通，结果有点意外”。
4. 情绪要可感知但不过载，正文需要回到具体过程和限制。
5. 低成本、平价、长期主义容易提升收藏，但不能编造价格和效果。
6. 正文常见结构是：具体场景 -> 原先困扰/误判 -> 发现过程 -> 真实感受 -> 限制/避坑 -> 互动。
7. 高互动内容不一定是完整产品说明，短标题和生活瞬间反而能让评论区补充讨论。

## Prompt 修正原则

这轮样本之后，Agent prompt 和规则层做了以下修正：

- 删除品类硬编码，不再把咖啡、控糖、无糖、成分等特定类目写进通用 prompt。
- 标题模板使用通用变量：场景、原先误判、轻反差、对象。
- `structure_agent` 优先生成“生活瞬间 + 轻情绪”的标题，而不是卖点列表标题。
- `humanizer_agent` 保留轻微情绪张力，但禁止新增用户未提供的事实细节。
- `compliance_agent` 做通用风险扫描，不使用特定品类词表假装事实校验。

## 局限

- 样本量小，只适合做 Agent 方法论种子，不适合做统计结论。
- 关键词偏“好物/生活/幸福感”，不是全品类爆款规律。
- 没抓评论正文，因此无法分析评论区需求和异议。
- 部分高互动笔记并非严格商品种草，但能提供小红书标题和内容互动机制参考。
- 这轮抓取使用可见浏览器复用登录态；后续若做实时趋势节点，应先尝试 headless，失败再降级到可见浏览器。

## 后续建议

1. 保留该数据作为 `trend_agent` 的内置通用模式，不要删除。
2. 后续接 MediaCrawler 时，新增独立 `market_research_agent`，不要把爬虫逻辑塞进 `trend_agent`。
3. 实时爬取只作为增强项，失败时回退到本地模式。
4. 若要扩展样本，应按商品类目分别建目录，避免不同品类规律混在一起。
